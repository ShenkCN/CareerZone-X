# 技术选型书

> 版本：2026-11-18  
> 目标：单机、低依赖、能离线解释、能换电脑复现；不为了“技术栈好看”引入重型组件。

## 1. 总体架构

```text
浏览器（用户手动打开招聘站）
  └─ Edge 扩展（当前页 DOM，仅点击触发）
        └─ POST /api/jobs/import
              └─ FastAPI + SQLAlchemy
                    ├─ SQLite：默认，本机单文件
                    ├─ Chroma：向量检索（可选/降级）
                    └─ DeepSeek HTTP API：初筛 + 两轮分析
Streamlit（127.0.0.1:8501）
  └─ 调用 FastAPI（127.0.0.1:8000）
```

前后端分离，但都只监听本机回环地址。

## 2. 为什么是这些组件

### FastAPI + Uvicorn

- 路由/参数校验/Swagger 清楚；
- Pydantic 模型让 API 契约可测试；
- Uvicorn 轻，单机足够；
- 比 Django 少很多模板/管理后台负担。

### Streamlit

- 个人工具不需要独立前端工程；
- 快速做表单、卡片、上传、图表；
- 缺点：每次 rerun 重跑脚本、复杂布局要用 CSS 补；
- 本机使用可接受。

### SQLAlchemy 2.x + SQLite

- 默认 SQLite：零安装、单文件、易备份；
- MySQL 8 保留：`scripts/switch_db.py` 可切；
- 本机 WSL MySQL 曾被外部服务管理器反复停止，导致随机 500，故默认 SQLite；
- 不是“放弃 MySQL”，而是把稳定性放在演示之前。

### DeepSeek：直接 HTTP，不用 OpenAI SDK

- 本机应用控制策略拦截过 `jiter` 等 DLL，OpenAI SDK 无法加载；
- 改用 `requests` 直接 POST `/chat/completions`；
- 仍然兼容 OpenAI 风格的 JSON 输出；
- 没有把 Key 写进代码，只从 `.env` 读。

### Chroma + 自定义 embedding

- Chroma 1.5.x 持久化；
- 本机 `torch/regex` 等 DLL 被策略拦截，默认 `VECTOR_TRY_MODEL=false`；
- 使用纯 Python hash-384（字符 bigram + 英文 token）降级；
- 这不是“语义最强”，但能让“找相似职位”在本机跑起来；
- 设置 `VECTOR_TRY_MODEL=true` 且有可用模型时才尝试 bge。

### Argon2id + 服务端会话

- 密码 Argon2id；
- 浏览器只拿随机 session token，数据库存哈希；
- 管理员密码通过后还要签名的 5 分钟挑战令牌 + 密保答案；
- 会话 Cookie 由前端 JS 写入（本机自用的取舍，非 HttpOnly）。

## 3. AI 调用策略

- 列表初筛：25—40 条/组，最多 3 组并发，输出 8192 token；
- 每页最多初筛 300 条，避免 1000 条页面把 Token 和时间打爆；
- 两轮分析：单条，第一轮结构化，第二轮匹配；
- 缓存键：`job_id + user_id + profile_hash`；
- 每次调用写 `api_usage`，管理员看用量；
- 失败降级：列表初筛失败→规则；两轮分析失败→报错，不伪造结果；
- **没有完整 JD 不做两轮分析**：列表采集 raw.mode=list 且无 hasDetail，或 JD <80 字，直接 422。

## 4. 采集方案

- Manifest V3；
- `activeTab` + `scripting`，用户点击才注入；
- 不做后台定时、不自动导航、不模拟点击、不绕验证码；
- 单次最多 1000 条；
- 可选 auto_detail.js 内容脚本：用户开启后，仅在当前可见详情变化时补采，不自动滚动/翻页；
- 当前版本无令牌：本机 API 只监听 127.0.0.1，单用户归属；
- 清空接口需要二次确认。

## 5. 安全与部署取舍

- 默认绑定 `127.0.0.1`，不暴露公网；
- CORS 只允许本机 UI；
- 上传大小、登录锁定、注册/忘记密码/催审批限流；
- 管理员密码固定且弱（用户指定）是已知风险，只本机；
- 若部署云服务器，必须加：
  - HTTPS 反向代理；
  - 强管理员密码/2FA；
  - HttpOnly + Secure Cookie；
  - 备份和访问日志；
  - 重新评估采集合规。
