# CareerZone X 产品说明书

> 版本：2026-11-18（按今晚实际操作重写）  
> 定位：个人自用的本地求职工作台，不是自动爬虫，也不是招聘平台官方客户端。  
> 默认数据库：SQLite（`storage/careerzone.db`）；MySQL 8 保留为可选方案。

## 1. 它解决什么问题

把“招聘网站上一堆职位”变成可解释的投递决策：

1. 用户自己打开 BOSS/猎聘/智联/51JOB/鱼泡；
2. 浏览器扩展**只在用户点击时**读取当前页；
3. 数据进入本机职位库；
4. 列表做一次轻量初筛；
5. 用户点进详情，若 JD 完整，再做“结构化 + 画像匹配”两轮分析；
6. 用户收藏、看历史、导出，自己决定投不投。

**边界：服务端不会主动访问招聘网站，不会自动翻页、自动点击、绕验证码。**  
自动批量抓取会碰平台条款和封号风险，这个产品不做。

## 2. 角色和入口

### 普通用户

- 注册后状态为 `pending`，必须管理员通过才能登录；
- 登录后：首页 / 职位板 / 收藏夹 / 浏览历史 / 设置 / 使用说明；
- 个人信息：显示名、头像、手机号、城市、求职类型、目标城市、目标岗位、技能、薪资、经验、学历、行业、公司规模；
- 简历：PDF/Word 上传、解析、版本、设为当前、回档；
- 设置：头像、简历、浏览器采集、反馈、改密；
- 登录会话：默认 12 小时；刷新页面免登录（Cookie），退出登录后清除。

### 管理员

- 固定账号 `Shenk`；
- 密码 + 密保问题二次验证；
- 注册审核/驳回、用户列表、账号管理；
- 账号管理：注册/最后登录、采集/收藏/浏览/活跃度、每批采集记录；
- 可按用户恢复一条/几条/全部已清空职位，处理恢复申请；
- 控制台统计、Token 用量、反馈处理、导出；
- 只能看管理员端，不进用户职位板。

## 3. 账号与密码规则（当前）

- 账号：**5—15 位**，只能字母/数字；纯字母、纯数字、混合都可以。
- 密码：**6—20 位**；纯数字、纯字母、混合都可以；不能有空格，只接受常见 ASCII 字符。
- 管理员密码固定，不可自助修改；忘记只能改数据库哈希/重建管理员。
- 登录连续失败默认锁定 15 分钟；注册接口有频率限制。

> 安全提示：纯数字密码是用户明确要求的便利性取舍，只适合本机自用。公网部署必须加 HTTPS、2FA，并恢复更强密码策略。

## 4. 浏览器采集（当前流程）

### 为什么是“点击采集”

招聘平台通常禁止自动化批量采集。扩展只做三件事：

1. 用户点扩展；
2. 扩展读取**当前页可见 DOM**；
3. POST 到本机 FastAPI。

不做：自动登录、自动翻页、自动滚动、自动点击“下一页”、破解验证码。

### 当前版本（0.4.0）

- **不需要采集令牌**：本机 `IMPORT_TOKEN_REQUIRED=false`；
- 扩展只填 API 地址 `http://127.0.0.1:8000`；
- 采集成功显示：新增 / 更新 / 跳过 / **重复率 = 更新 ÷ (新增+更新)**；
- 有“清空我的职位板”按钮，二次确认后把 A 的采集关系标记为已清空：A 看不到；B 如果没有自己采过这批职位，也看不到；B 自己采过的副本仍保留；可在历史页申请恢复；
- 单次最多 1000 条；职位板单页最多显示 **1000 条**；
- 列表页右侧如果已经显示当前选中职位的完整 JD，会一并采集这一条；
- 可开启 **“浏览时自动补全当前可见 JD”**：你滚动/打开职位页时，扩展读取当前可见详情并补全，不自动滚动/翻页；
- 其他卡片只有摘要，**不冒充完整 JD**。

### 列表采集 vs 详情采集

- 列表页：采卡片摘要，适合先入库、先初筛；
- 详情页：采完整 JD；同一个 URL 会更新已有职位；
- App 详情页只有摘要时，会显示黄色警告，并禁用“开始两轮分析”；
- 想分析某个职位：打开原站详情页 → 点扩展“采集当前页” → 回 App 重新进详情。

## 5. 职位板

- 关键词：岗位/公司/技能/描述模糊搜索；
- 来源、城市、求职类型、薪资、经验、学历、行业、公司规模；
- 城市支持 `苏州/上海`、`苏州,上海`、`苏州、上海`，按 OR 匹配；
- “不限”在前后端都视为不筛选；
- “清空筛选”一键回到默认（换 form key，真正清空输入框）；
- 单页最多 1000 条；首次进入先秒出列表，不自动跑 AI；
- 点“搜索”时按开关决定是否 AI 初筛；
- AI 初筛：每 40 条一组、最多 3 组并发、每页最多 300 条；超过 300 条的其余职位显示“尚未分析”，详情按需分析；
- “换一批”排除已展示职位；重复率过高会提示；
- 职位卡：匹配分、推荐档位、AI 理由、收藏、原站投递；公司名会做清洗，拿不准显示“未知公司”。

## 6. AI 两轮分析

1. 第一轮：从完整 JD 抽取职责、要求、技能、风险；
2. 第二轮：结合画像输出匹配点、缺口、风险、简历角度、面试问题；
3. 结果按 `profile_hash` 缓存；画像改了会重算；
4. **没有完整 JD 不允许分析**：
   - 列表采集 / JD 少于 80 字 → 422；
   - 前端按钮禁用并显示原因；
   - 不再让模型只看标题硬编。

## 7. 首页和设置

- 首页：问候、头像（无头像显示默认鱼）、画像完善度、简历/收藏/目标岗位统计、下一步、最近浏览最多；
- 头像：设置 → 账号与头像 → 上传 PNG/JPG/WebP（≤2MB）；显示在左下角、首页、设置；
- 画像保存：顶部提示 + “去职位板”按钮；
- 反馈：用户提交，管理员回复；
- 采集统计：职位板顶部显示“上次采集：新增/更新/跳过/重复率”；
- 登录页小游戏：接鱼 20 秒、猜数字 10 次、贪吃蛇；结果会被大肥鱼点评；
- 已清空职位：浏览历史页底部选择一条/几条/全部申请恢复。

## 8. 当前已知限制

- 服务端不自动抓取；每条完整 JD 仍需用户在详情页点一次采集；
- 扩展只支持桌面 Edge/Chrome，不支持手机浏览器装扩展；
- 单次采集最多 1000 条；浏览补全不会自动翻页，滚太快可能漏采，可放慢；
- AI 每页最多初筛 300 条，1000 条页面不会全部分析；
- 数据默认只在本机，没有云同步；公网部署见 docs/华为云部署指南.md；
- 管理员密码固定且较弱，只可本机使用；公网必须换强密码；
- MySQL 方案保留，但本机 WSL MySQL 曾出现外部进程反复停止，默认改用 SQLite。
